## 1. 概要

### 1.1 本ドキュメントの目的

本ドキュメントは、要件定義書（01-requirements.md）で定義された要件を実現するための、システムの外部仕様を定義する。内部実装の詳細は詳細設計書に委ねる。

### 1.2 設計方針

本プロジェクトの基本設計は以下の方針に従う。

- コマンドラインインターフェースのみを提供する単一バイナリのCLIツールとする
- ステートレスな設計とし、永続データは持たない
- 外部サービス（LLMプロバイダ）への依存を抽象化し、将来の拡張性を確保する
- 既存の開発ワークフロー（Git、静的解析ツール）と併用可能な設計とする

### 1.3 要件とのトレーサビリティ

本設計書の各項目は、要件定義書の要件IDと対応付けられている。対応関係は各設計項目内で明記する。

## 2. システム構成

### 2.1 システム構成概要

本システムは、利用者のローカル環境で動作するCLIアプリケーションである。外部サービスとしてLLMプロバイダのAPIを利用する。

```text
┌───────────────────────────────────────────────────┐
│                利用者のローカル環境                   │
│                                                   │
│  ┌──────────┐      ┌──────────────┐               │
│  │  利用者   │─────▶│  lrv (CLI)   │               │
│  └──────────┘      └──────┬───────┘               │
│                           │                       │
│                           ▼                       │
│                  ┌──────────────┐                 │
│                  │  Gitリポジトリ │                 │
│                  └──────────────┘                 │
│                                                   │
└──────────────────────────┬────────────────────────┘
                           │ HTTPS
                           ▼
                  ┌────────────────┐
                  │  LLMプロバイダ   │
                  │  (Anthropic)   │
                  └────────────────┘
```

### 3.3 機能詳細

#### BD-F-001 コマンド起動・オプション解析機能

利用者が入力したコマンドとオプションを解析し、後続処理に渡す。

| 項目     | 内容                                                   |
| -------- | ------------------------------------------------------ |
| 対応要件 | FR-009, FR-010, FR-011                                 |
| 入力     | コマンドライン引数                                     |
| 出力     | 解析済みのオプション値                                 |
| 異常系   | 不正なオプション指定時はエラーメッセージを出力して終了 |

#### BD-F-002 差分取得機能

Gitリポジトリから、現在のブランチとベースブランチ間の差分情報を取得する。

| 項目     | 内容                                                             |
| -------- | ---------------------------------------------------------------- |
| 対応要件 | FR-001                                                           |
| 入力     | ベースブランチ名                                                 |
| 出力     | 変更ファイルのリスト、各ファイルの差分内容、各ファイルの全体内容 |
| 前提     | 実行ディレクトリがGitリポジトリ配下であること                    |
| 異常系   | Gitリポジトリ外での実行時はエラー出力                            |

#### BD-F-003 ベースブランチ決定機能

オプション指定および自動検出により、差分取得で使用するベースブランチを決定する。

| 項目         | 内容                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| 対応要件     | FR-001, FR-010                                                           |
| 決定優先順位 | 1. --base オプションの指定 > 2. 現在のブランチの分岐元自動検出           |
| 異常系       | 自動検出に失敗した場合、利用者に明示的な指定を促すエラーメッセージを出力 |

自動検出のアルゴリズムは詳細設計書で定義する。

#### BD-F-004 レビュー実行制御機能

差分情報を受け取り、観点別レビューを並行実行し、結果を統合する。

| 項目         | 内容                                             |
| ------------ | ------------------------------------------------ |
| 対応要件     | FR-002, FR-003, NFR-004                          |
| 入力         | 差分情報、実行対象観点のリスト                   |
| 出力         | 観点別のレビュー結果                             |
| 部分失敗許容 | 一部の観点が失敗しても、成功した観点の結果を返す |

#### BD-F-005〜007 観点別レビュー機能

各観点について、LLMにレビューを依頼し、指摘のリストを取得する。

| 設計ID   | 観点           | 検出対象                                          | 対応要件 |
| -------- | -------------- | ------------------------------------------------- | -------- |
| BD-F-005 | パフォーマンス | N+1問題、キュー化すべき同期処理                   | FR-004   |
| BD-F-006 | セキュリティ   | マスアサインメント、SQLインジェクション、認証関連 | FR-005   |
| BD-F-007 | 設計・可読性   | Fat Controller、サービス責務越境、深いネスト      | FR-006   |

各観点に対して専用のプロンプトを用意する。プロンプトの詳細は詳細設計書で定義する。

#### BD-F-008 確信度判定機能

各指摘に対して、3段階の確信度ラベル（高・中・低）を付与する。

| 項目     | 内容                              |
| -------- | --------------------------------- |
| 対応要件 | FR-007                            |
| 判定主体 | LLMがプロンプトの指示に従って判定 |
| ラベル値 | high / medium / low               |

判定基準は各観点のプロンプトに組み込む（詳細設計書で定義）。

#### BD-F-009 結果統合機能

複数観点のレビュー結果を1つの出力データに統合する。

| 項目           | 内容                                                   |
| -------------- | ------------------------------------------------------ |
| 対応要件       | FR-003, NFR-004                                        |
| 統合ルール     | ファイル単位でグルーピングし、行番号順にソート         |
| 失敗観点の扱い | 失敗した観点は出力から除外し、サマリーに失敗情報を付記 |

#### BD-F-010 Markdown出力機能

統合されたレビュー結果をMarkdown形式に整形し、指定された出力先に書き出す。

| 項目     | 内容                                                  |
| -------- | ----------------------------------------------------- |
| 対応要件 | FR-008, FR-009                                        |
| 出力形式 | Markdown                                              |
| 出力先   | 標準出力（デフォルト）またはファイル（-o オプション） |
| 出力構造 | サマリー部 + ファイル別詳細部                         |

出力構造の詳細は「4. 入出力設計」に記載する。

## 4. 入出力設計

### 4.1 コマンドインターフェース

#### 4.1.1 コマンド書式

```bash
lrv [オプション]
```

#### 4.1.2 オプション一覧

| オプション | 短縮形 | 引数                   | 必須 | デフォルト | 説明                             | 対応要件 |
| ---------- | ------ | ---------------------- | ---- | ---------- | -------------------------------- | -------- |
| --base     | -      | ブランチ名             | 否   | 自動検出   | 差分取得時のベースブランチを指定 | FR-010   |
| --output   | -o     | ファイルパス           | 否   | 標準出力   | 出力先を指定                     | FR-009   |
| --focus    | -      | 観点名（カンマ区切り） | 否   | 全観点     | レビュー観点を絞り込む           | FR-011   |
| --help     | -h     | -                      | 否   | -          | ヘルプを表示                     | -        |
| --version  | -v     | -                      | 否   | -          | バージョンを表示                 | -        |

#### 4.1.3 --focus オプションの指定可能値

| 値          | 対象観点           |
| ----------- | ------------------ |
| performance | パフォーマンス観点 |
| security    | セキュリティ観点   |
| design      | 設計・可読性観点   |

複数指定する場合はカンマで区切る（例: `--focus=performance,security`）。

#### 4.1.4 実行例

```bash
# 最もシンプルな実行（分岐元を自動検出、標準出力）
$ lrv

# ベースブランチを明示指定
$ lrv --base develop

# 結果をファイルに保存
$ lrv -o review.md

# セキュリティ観点のみ実行
$ lrv --focus=security

# ベースブランチ指定 + ファイル出力 + 観点絞り込みの組み合わせ
$ lrv --base develop -o review.md --focus=security,performance
```

## app/Http/Controllers/UserController.php

### L45 [パフォーマンス][確信度: 🔴 高] N+1問題の可能性

foreachループ内で$user->postsを呼び出しているため、ユーザー数分のクエリが発行されます。
コントローラーメソッドの冒頭で User::with('posts')->get() として事前ロードしてください。

```php
foreach ($users as $user) {
    echo $user->posts->count();
}
```

### L120 [設計][確信度: 🟡 中] Fat Controllerの兆候

storeメソッドが80行を超えています。バリデーション後のユーザー作成処理と
メール送信処理を UserRegistrationService などに切り出すことを推奨します。

## 6. メッセージ設計

### 6.1 メッセージ体系

メッセージは以下のカテゴリに分類される。

| カテゴリ         | 出力先                 | 用途                   |
| ---------------- | ---------------------- | ---------------------- |
| 進捗メッセージ   | 標準エラー出力         | 処理の進行状況を伝える |
| レビュー結果     | 標準出力またはファイル | 本来の成果物           |
| エラーメッセージ | 標準エラー出力         | 異常発生時の情報       |

進捗メッセージとエラーメッセージを標準エラー出力に分離することで、レビュー結果のみをファイルにリダイレクトする利用が可能となる。

| タイミング         | メッセージ例                 |
| ------------------ | ---------------------------- |
| 差分取得完了       | 変更ファイル数を表示         |
| 観点別レビュー開始 | 実行対象の観点リストを表示   |
| 観点別レビュー完了 | 各観点の完了と検出件数を表示 |
| 全体完了           | 実行時間と総指摘件数を表示   |

### 6.3 メッセージコード体系

将来の多言語対応やエラー追跡のため、主要メッセージにはコードを付与する。

| コード範囲 | 用途                          |

具体的なコード定義は詳細設計書で行う。

## 7. エラー設計

### 7.1 エラー分類

発生しうるエラーを以下に分類する。各分類には、対応するセンチネルエラーを明示する。

| 分類               | 代表例                                               | 該当センチネルエラー                                                    | 終了コード | 対応要件                  |
| ------------------ | ---------------------------------------------------- | ----------------------------------------------------------------------- | ---------- | ------------------------- |
| 利用者入力エラー   | 不正なオプション、存在しないブランチ                 | `ErrInvalidAspect`, `ErrBranchNotFound`                                 | 1          | NFR-006                   |
| 実行環境エラー     | Gitリポジトリ外、APIキー未設定、分岐元の自動検出失敗 | `ErrNotGitRepository`, `ErrAPIKeyMissing`, `ErrNoBaseDetected`          | 2          | NFR-006, PRE-002, PRE-003 |
| 外部サービスエラー | LLM API呼び出し失敗、タイムアウト、認証エラー        | `ErrAPIAuthFailed`, `ErrAPITimeout`, `ErrAPIUnexpectedResponse`         | 3          | NFR-005, NFR-006          |
| 内部エラー         | 想定外の例外、リクエスト組み立て失敗、応答パース失敗 | `ErrRequestBuildFailed`, `ErrParseResponse`, およびその他の未分類エラー | 4          | NFR-006                   |

終了コードの分類軸は「エラーの原因」であり、トピックドメインではない。例えば `ErrNoBaseDetected`（分岐元の自動検出失敗）は、Gitブランチに関連するが、利用者の入力ミスではなく実行環境（リポジトリのブランチ構成）に起因するため、利用者入力エラー（コード1）ではなく実行環境エラー（コード2）に分類する。

内部エラー（コード4）は `determineExitCode` の `default` に該当する。`ErrRequestBuildFailed`・`ErrParseResponse` は明示的なセンチネルだが利用者に対処手段がないため固有メッセージを持たせず、未分類エラーと同じく汎用メッセージで応答する。

### 7.2 エラーメッセージの設計原則

| 原則             | 内容                                                       |
| ---------------- | ---------------------------------------------------------- |
| 原因の明示       | 何が原因でエラーになったかを具体的に伝える                 |
| 対処方法の提示   | 利用者が次に何をすべきかを提示する                         |
| 機密情報の除外   | APIキーやトークン等を含めない（NFR-008）                   |
| 言語             | 利用者は開発者であり、CLIツールの慣例に従い英語で出力する  |
| 生成と提示の分離 | エラーの生成（下位層・機械可読）と提示（利用者向け）を分離 |

対処方法を含む利用者向けメッセージは、各センチネルエラーの定義文字列自体に英語で記述する。下位層では生エラーを `slog` で開発者向けに記録し、利用者向け出力には浄化済みのセンチネルエラーのみを伝播させる。未知のエラー（コード4）は機密情報混入の恐れがあるため、生エラーの内容を出力せず固定の汎用メッセージで応答する。

### 7.3 主要なエラーケースと応答

応答メッセージは英語で出力する。以下に各センチネルエラーの応答文字列を示す。

| エラーケース                 | 対応エラー                 | 応答内容                                                                           |
| ---------------------------- | -------------------------- | ---------------------------------------------------------------------------------- |
| APIキー未設定                | `ErrAPIKeyMissing`         | ANTHROPIC_API_KEY is not set; set the environment variable and try again           |
| Gitリポジトリ外で実行        | `ErrNotGitRepository`      | not a git repository; run lrv inside a git repository                              |
| 存在しないベースブランチ指定 | `ErrBranchNotFound`        | specified branch does not exist; check the branch name and try again               |
| 分岐元の自動検出失敗         | `ErrNoBaseDetected`        | could not detect the base branch automatically; specify one explicitly with --base |
| 不正な観点指定               | `ErrInvalidAspect`         | invalid aspect; valid values are performance, security, design                     |
| LLM APIタイムアウト          | `ErrAPITimeout`            | API request timed out; check your network or increase LRV_TIMEOUT                  |
| LLM API認証エラー            | `ErrAPIAuthFailed`         | API authentication failed; verify that your API key is valid                       |
| LLM API異常応答              | `ErrAPIUnexpectedResponse` | unexpected response from API; please try again later                               |
| 想定外の内部エラー           | コード4該当                | an unexpected error occurred; please try again                                     |

### 7.4 部分失敗時の挙動

NFR-004に従い、一部の観点レビューが失敗しても他の観点の結果を出力する。

| 状況         | 挙動                                                                          |
| ------------ | ----------------------------------------------------------------------------- |
| 全観点成功   | 正常終了（終了コード0）、すべての結果を出力                                   |
| 一部観点失敗 | 正常終了（終了コード0）、成功した観点の結果を出力し、サマリーに失敗観点を明記 |
| 全観点失敗   | 異常終了（終了コード3）、エラーメッセージを出力                               |

## 9. 技術選定

### 9.1 言語・ランタイム

| 項目       | 選定内容    | 選定理由                                                                    |
| ---------- | ----------- | --------------------------------------------------------------------------- |
| 言語       | Go          | CON-001により指定。並行処理の記述性、単一バイナリ配布、標準ライブラリの充実 |
| バージョン | Go 1.22以降 | 安定版の利用、errgroup等の並行処理パッケージ活用                            |

### 9.2 主要ライブラリ

| 用途                | 選定ライブラリ                  | 選定理由                                         |
| ------------------- | ------------------------------- | ------------------------------------------------ |
| CLIフレームワーク   | spf13/cobra                     | デファクトスタンダード、オプション設計の実績     |
| 並行処理制御        | golang.org/x/sync/errgroup      | 複数goroutineのエラー統合管理                    |
| LLM APIクライアント | net/http（標準ライブラリ）      | 学習目的で自作、ストリーミング処理の理解を深める |
| Git操作             | os/exec（標準ライブラリ）       | 外部依存を増やさず、gitコマンドを直接利用        |
| JSON処理            | encoding/json（標準ライブラリ） | 追加ライブラリ不要                               |

### 9.3 LLMプロバイダ・モデル

| 項目       | 選定内容                    | 選定理由                            |
| ---------- | --------------------------- | ----------------------------------- |
| プロバイダ | Anthropic                   | APIの安定性、レビュー用途への適性   |
| 既定モデル | Claude Sonnet系             | NFR-016のコスト・精度バランスを考慮 |
| モデル切替 | 環境変数LRV_MODELで切替可能 | NFR-014に基づく柔軟性確保           |

### 9.4 選定時に比較・除外した代替案

| 項目              | 代替案                      | 除外理由                                         |
| ----------------- | --------------------------- | ------------------------------------------------ |
| CLIフレームワーク | urfave/cli、標準flag        | Cobraの方がサブコマンド拡張性・将来性で優位      |
| LLMクライアント   | 公式SDK（anthropic-sdk-go） | 学習目的のため自作を選択。将来的な差し替えは可能 |
| Git操作           | go-git                      | ローカルGitコマンドで十分、依存を増やさない方針  |
