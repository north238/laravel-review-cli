# lrv

**lrv (Laravel Review CLI)** は、プルリクエストを作成する前に、あなた自身のコードを LLM でセルフレビューするためのコマンドラインツールです。

PHPStan や Larastan のような静的解析ツールは、型や構文の問題は的確に見つけてくれます。しかし、N+1 問題やマスアサインメント脆弱性、Fat Controller のような **「文脈を読まないと判断できない問題」** は、静的解析では拾いきれません。こうした問題は、たいてい PR を出した後のレビューで初めて指摘され、手戻りの原因になります。

lrv は、この隙間を埋めます。変更差分を **パフォーマンス・セキュリティ・設計/可読性** の 3 つの観点から並行してレビューし、それぞれの指摘に **確信度（高・中・低）** を付けた Markdown レポートを出力します。PR を出す前の最後のセルフチェックとして、レビュアーに指摘される前に自分で気づくことを助けます。

---

## 静的解析ツールとの役割分担

lrv は PHPStan / Larastan / Laravel Pint を **置き換えるものではなく、補完するもの** です。それぞれ得意な領域が異なります。

|            | 静的解析ツール（PHPStan 等）                                       | lrv                                                          |
| ---------- | ------------------------------------------------------------------ | ------------------------------------------------------------ |
| 得意な検出 | 型エラー、未定義メソッド、コーディングスタイル、構文レベルの不整合 | 文脈依存の問題（N+1、マスアサインメント、Fat Controller 等） |
| 判断の性質 | 決定的（ルールに合致するか）                                       | 推論的（コードの意図を読んで判断）                           |
| 結果の確度 | 基本的に確実                                                       | 確信度ラベルで確からしさを提示                               |
| 位置づけ   | まず通すべき土台                                                   | その上での気づき支援                                         |

**推奨する使い方は「両方を使う」ことです。** まず PHPStan などで機械的に検出できる問題を潰し、その上で lrv を実行して、静的解析では拾えない文脈依存の問題に気づく——という流れを想定しています。lrv は型チェックやスタイル違反のような、既存ツールが得意とする領域は検出対象から除外しています。

---

## ⚠️ コードが外部に送信されることについて

lrv は、レビュー対象のコード（変更差分および変更ファイルの全体内容）を **Anthropic の API に送信** します。これはツールの動作上避けられません。

利用にあたって、以下を理解しておいてください。

- レビュー対象のソースコードが、外部の LLM プロバイダ（Anthropic）に送信されます。
- **機密性の高いコードや、外部送信が許可されていないコードでの利用は推奨しません。** 業務で利用する場合は、所属組織のポリシーを確認してください。
- API キーはあなた自身のものを使用し、LLM の利用料金はあなたの負担となります。

送信されるのは差分と変更ファイルの内容のみで、lrv がコードを外部に保存したり、送信先以外に共有したりすることはありません。

## 前提条件

lrv を利用するには、以下が必要です。

| 前提               | 内容                                                                 | 確認方法                                                   |
| ------------------ | -------------------------------------------------------------------- | ---------------------------------------------------------- |
| Go                 | ソースからビルドするため、Go の実行環境が必要です（1.22 以降を推奨） | `go version`                                               |
| Git                | 内部で git コマンドを使用して差分を取得します                        | `git --version`                                            |
| Anthropic API キー | LLM によるレビューに使用します                                       | [Anthropic Console](https://console.anthropic.com/) で取得 |
| インターネット接続 | LLM API との通信に必要です                                           | —                                                          |

また、レビュー対象は **Git で管理された Laravel プロジェクト** であることを前提としています。

## インストール

Go の環境が整っていれば、`go install` でインストールできます。

```bash
go install github.com/north238/laravel-review-cli/cmd/lrv@latest
```

インストール後、`lrv` コマンドが `$GOPATH/bin`（通常は `~/go/bin`）に配置されます。このディレクトリに PATH が通っていることを確認してください。

```bash
# インストールの確認
lrv --version
```

> **`lrv: command not found` と表示される場合**
> `~/go/bin` に PATH が通っていない可能性があります。以下をシェルの設定ファイル（`~/.zshrc` や `~/.bashrc`）に追加してください。
>
> ```bash
> export PATH="$PATH:$(go env GOPATH)/bin"
> ```

## API キーの設定

lrv は Anthropic API キーを **環境変数** から読み込みます。ソースコードや設定ファイルにキーを書く必要はありません。

```bash
export ANTHROPIC_API_KEY="sk-ant-xxxxxxxxxxxxxxxx"
```

毎回設定する手間を省くには、シェルの設定ファイル（`~/.zshrc` や `~/.bashrc`）に追記してください。

### 任意の環境変数

以下は必須ではありませんが、必要に応じて設定できます。

| 環境変数            | 用途                           | デフォルト                   |
| ------------------- | ------------------------------ | ---------------------------- |
| `ANTHROPIC_API_KEY` | Anthropic API キー（**必須**） | —                            |
| `LRV_MODEL`         | 使用する LLM モデル ID         | lrv が定めるデフォルトモデル |
| `LRV_TIMEOUT`       | API 呼び出しのタイムアウト秒数 | `120`                        |

`LRV_MODEL` を指定しない場合、lrv はあらかじめ定められたデフォルトのモデルを使用します。別のモデルを使いたい場合は、指定可能なモデル ID を [Anthropic 公式ドキュメント](https://platform.claude.com/docs/en/about-claude/models/overview) で確認して設定してください。

```bash
# 例: 使用するモデルを明示的に指定する
export LRV_MODEL="使用したいモデル ID"
```

## 使い方

lrv は Laravel プロジェクトのルートディレクトリで実行します。オプションなしで実行すると、現在のブランチと分岐元の差分を、全観点でレビューします。

```bash
# 最もシンプルな実行（分岐元を自動検出し、結果を標準出力に表示）
lrv

# ベースブランチを明示的に指定
lrv --base develop

# レビュー結果をファイルに保存
lrv -o review.md

# セキュリティ観点のみを実行
lrv --focus=security

# 複数のオプションを組み合わせる
lrv --base develop -o review.md --focus=security,performance
```

### 出力例

lrv を実行すると、以下のような Markdown 形式のレビュー結果が出力されます。

````markdown
# コードレビュー結果

## サマリー

### 確信度別件数

- 🔴 高: 3 件
- 🟡 中: 5 件
- 🟢 低: 2 件

### 観点別件数

- パフォーマンス: 4 件
- セキュリティ: 3 件
- 設計・可読性: 3 件

### 実行情報

- ベースブランチ: main
- 現在のブランチ: feature/user-management
- 変更ファイル数: 7
- 実行時刻: 2026-04-24 09:15:00

---

## app/Http/Controllers/UserController.php

### L45 [パフォーマンス][確信度:高] N+1 問題の可能性

foreach ループ内で $user->posts を呼び出しているため、ユーザー数分のクエリが
発行されます。コントローラーメソッドの冒頭で User::with('posts')->get() として
事前ロードしてください。

```php
foreach ($users as $user) {
    echo $user->posts->count();
}
```
````

指摘には観点カテゴリ・確信度・行番号が付き、ファイル単位で整理されます。確信度が「低」の指摘は推測の要素が強いため、参考程度に捉えてください。

## オプション一覧

| オプション  | 短縮形 | 引数                   | デフォルト | 説明                                   |
| ----------- | ------ | ---------------------- | ---------- | -------------------------------------- |
| `--base`    | —      | ブランチ名             | 自動検出   | 差分取得時のベースブランチを指定します |
| `--output`  | `-o`   | ファイルパス           | 標準出力   | レビュー結果の出力先を指定します       |
| `--focus`   | —      | 観点名（カンマ区切り） | 全観点     | レビューする観点を絞り込みます         |
| `--help`    | `-h`   | —                      | —          | ヘルプを表示します                     |
| `--version` | `-v`   | —                      | —          | バージョンを表示します                 |

### `--focus` で指定できる観点

| 値            | 対象                                                                   |
| ------------- | ---------------------------------------------------------------------- |
| `performance` | パフォーマンス観点（N+1 問題、キュー化すべき同期処理）                 |
| `security`    | セキュリティ観点（マスアサインメント、SQL インジェクション、認証関連） |
| `design`      | 設計・可読性観点（Fat Controller、責務越境、深いネスト）               |

複数の観点を指定する場合はカンマで区切ります（例: `--focus=performance,security`）。
